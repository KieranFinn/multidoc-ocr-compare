# KCI 题录抽取轮次收敛（需要"智能"的那一跳）

本 skill 固化"失败样本 → 抽取策略"的归纳方法。机械部分（回归闸门/失败档案/刊例路由/
守卫影响面/样本回归）已代码化：`meta_diff.py`（闸门）、`failures.py`（档案）、
`metapy/journals.py`（刊例注册表）、`guardmap.py`（改守卫前查谁在用它）、
`golden.py`（修好的篇目存标准答案，改完秒级回归）、
`why.py`（口径统一查询：一篇/一刊五处说法聚合 + 冲突检测）。
本文件只做**模式归纳与策略设计**那一跳，以及每跳的红线。

## 口径权威序（2026-11-24 定，先读这条再动手）

同一问题散在五处且互相漂移。查之前先跑 `python why.py <doc|刊名>`，按下面的权威序取值，
不要凭印象挑一处信：

| 问题 | 唯一权威 | 其余只作参考 |
|---|---|---|
| 红不红、缺什么 | `qc.qc_of()` | 备注/台账都不覆盖 QC |
| 这个刊什么体例 | `metapy/journals.py` 族表 + DOI 注册表 + `qc._NO_VOL_JOURNALS` | 三处口径若打架，`why.py --journal` 会标 ⚠，先修一致再判 |
| 字段值从哪来 | `metadata.json` 的 `confidence.source` / `webfill` | 产物自带出处，不靠备注猜 |
| 当初为什么这么判 | `reviewed_docs.json`（冻结档案，只解释过去） | 不判现在，与 QC 冲突时以 QC 为准 |
| GUI 上显示的备注 | 工作区 `gui_notes.json`（可被回填脚本覆盖） | 展示文字，非判据 |
| 守卫为什么存在 | 就近代码注释实证 | 改守卫前必读 |

`python why.py --audit` 全库扫"备注称已齐但 QC 仍红 / 台账记通过但 QC 红"的冲突。
漂移一旦被 `why.py` 标出，**先修口径源、再改产物**，不要在备注里打补丁绕过。

## 何时启动一轮

- QC 红单出现**新面孔**（不是已登记的证据缺失型）；
- 新一批 uploads 入库跑完全链之后；
- 有人想改 `metapy/front.py` / `metapy/issue.py` 的任何守卫（先读"改守卫的纪律"）。

## 第一步：失败档案与聚类（机械，先跑）

```bash
cd KCI/pipeline
# 工作区: failures/meta_diff/stages 三 CLI 都认 --ws <名或路径>; 不设时按
# --ws > KCI_WS_ROOT 环境变量 > GUI 当前工作区(.gui_prefs.json) > 主库 解析,
# 开跑前打印一行解析结果, 确认没跑错库再继续。
# 记一轮台账: 聚类 + 跟上轮对比 + 刷新进度报告(_rounds_report.html, 给人看的)
# --tokens 从界面抄这轮的 token 消耗(没有自动来源, 不填则报告里写"没记录")
# --did 一句话说清这轮怎么收敛的
python failures.py --round --tokens <N> --did "这轮做了什么"
python meta_diff.py snapshot      # 改动前快照(闸门基准)
```

聚类/台账输出里"可修线索 > 0"的簇优先（有 DOI/日期行/关键词行 = 原文大概率有证据，
属抽取缺口）；线索 0 的簇先怀疑证据缺失。每组都要写原因(备注), 报告里"有没写原因的"
会标红。台账会盯两种危险信号并直接打印: **连续两轮没动的组**（当初诊断错或该上 LLM）
和**新冒出来的组**（警惕是改代码改出来的）。每个簇对照 `metapy/journals.py` 查
"这条路归谁管、已知缺口"，**已在 gaps 里登记过的别再挖**（那是备注型）。

## 第二步：模式归纳（本 skill 的核心，只有这步需要你）

对目标簇逐篇打开查看器（`out/<doc>/viewer_compare.html`，三渠道并排 + 坐标框图），回答三问：

1. **原文有没有？** 三渠道一致没有 → 证据缺失，**写备注，不改代码**（铁律：不许臆造值凑绿）。
   备注写法见 `gui_notes.json` 现有条目（一句话说清"原文未印 X 证据 + 依据"）。
2. **有，抽在哪？** 定位块（类型/位置）与行形态：行首词、分隔符、与题名/摘要的相对位置。
   三渠道读法不一致时，以两家一致的为准，第三家当 OCR 噪声参考。
3. **为什么会漏？** 在 `metapy/front.py` / `issue.py` 里找到管这条路的现有守卫，
   弄清它的触发条件与本篇形态差在哪。**改守卫之前先能量化影响面**：
   这个形态签名在全库会命中多少篇（用 Grep/小探针量，探针要先用已知案例校验——
   交接文档 §7：探针会静默失败）。

## 第三步：设计策略（模板，不是散规则）

新判据一律写成三要素，缺一项就不许合入：

- **触发器**：刊例匹配优先（DOI 前缀/刊名 → `metapy/journals.py` 加族或挂到现有族），
  通用行形态正则次之。触发越宽，误报边界必须说得越细。
- **动作**：只填空、不覆盖已有值（`只填空不覆盖` 是 issue.py 现成口径，照抄）。
- **误报边界**：必须能回答"什么形态会被这条误伤"。说不出 = 不许加（铁律：能不做就不做）。

同时在两处互指登记：`metapy/journals.py` 该族的 `extractor` 字段 + 守卫注释里的实证篇号，
并在 front/issue 的 `_selftest` 里加用例（照抄现有 case 风格，blk 字典 + issue_doc/front_doc 级断言）。

改守卫的准入前查（2026-11-24 新增，防"牵一发而动全身"靠脑补）：
```bash
python guardmap.py <守卫名>     # 先看全库谁在用它; 命中别的阶段=生效面外溢, 优先改走刊例族内路由
python golden.py run --ws <区>  # 改完跑黄金样本, 已有样本必须全绿才算没改坏
```

## 第四步：准入闸门（机械，跑完才准入）

```bash
python stages.py --batch <本簇篇目> front,abs,issue      # 只重跑目标簇, 绝不顺手全库
python meta_diff.py diff                                  # 三道闸:
#   a. QC 恶化表必须空 (ok/novol -> bad = 0)
#   b. 字段组统计里可疑组合逐篇过 (如 volume/issue 互换 → 必须对页眉印刷证据)
#   c. _meta_diff_<tag>.json 人工抽验变更值
```

闸门不过 → 回滚（单篇从快照 zip 取回该字段）或收窄守卫，再来一轮。
**全库重跑只在一种情况下做**：闸门脚本本身或底层数据结构变了，且做好 700+ 篇 diff 审查的准备。

## 红线（铁律，逐条来自 2026-11-18 的教训）

1. 原文确实没有的字段就是没有 —— 写备注，不改质检口径，不编值。
2. 未勾选的阶段一律不执行 —— 只重跑本簇篇目与本簇相关的阶段。
3. 先量后改 —— 新判据先报全库命中数与误报边界，再给 diff 对比。
4. 能不做就不做 —— 每条新守卫都要说清误报边界；说不清就别加。
5. title/title_en/authors 是展示字段，QC 只看齐全性 —— 值劣化的容忍度可以低，
   但红单永远以 QC 为准；**唯一例外是假绿**（垃圾值凑的绿，纠正它必然变红，这是好事，要在报告里说明）。
6. 两例 2026-11-18 实锤教训：
   - 守卫改宽了修好 10 篇、大库翻出 700 篇旧账（其中部分是潜伏 bug，部分是误伤）——
     所以每轮必须快照 + 只重跑目标簇 + diff 三道闸；
   - JNAH 的 DOI 四段读法与 kjcss 相反 —— **同形态不同刊可能语义相反**，
     卷期类判据必须对页眉印刷证据，不能照抄别刊先例。

## 回填产物的三件套与备注定稿格式(2026-11-19)

任何非原文来源的回填(联网/注册表/账本), 产物必须三件套齐全:
1. 字段级 `confidence.source` 标明来源(web_record / doi_registry / sibling_issue);
2. metadata 顶层 `webfill` 字段列出被联网回填的字段名(GUI 备注列据此加 🌐 标);
3. 备注一律用定稿格式, **已回填与仍缺都要写**:
   `[回填:联网检索] 已回填:卷/期; 原文仍缺:引文(脚注二选一)。来源:KCI官方著录。`
   (缺项=质检口径中文名, 全齐写"无(必抽项已齐)"; 来源写短名: KCI官方著录/doi.org/KISS/DBpia。
   备注不要堆历史上下文——已回填/仍缺本身就是完整信息, 旧描述会在回填后变成错误陈述。)
   生成函数: `metapy.webfill.note_line(result, miss)`; 人工批处理参照 journal_toc_fill.py。

## LLM 什么时候进场

上面四步卡住时才上，且只辅助第二步（读失败档案、对照样例、提议规则草稿），
准入闸门永远走代码。触发条件：同一聚类规则两改两错；或新刊例涌入速度超过人工模板化。
到那时再议后训练——当前规则几十条、每条有实证边界，远没到那个量级。
